# step2. 도메인 설계

**산출물**: `domain-<slug>.md` 파일 하나

**흐름**:
1. `plan` skill 호출 (Skill tool, skill="plan") — 메인 Claude 가 직접 수행
2. 선택 필요 시 사용자에게 질문
   - 사용자가 되물으면 답변만, 그 후 다시 선택지 질문
3. **외부 리서치는 메인 Claude(메인 에이전트) 가 직접 수행한다.** 서브에이전트 위임하지 않음 — WebSearch / WebFetch / 라이브러리 문서 조회 등 메인 도구로 직접 조사.
   - 라이브러리 비교, current trends, 보안 권장사항, API 사용법 등 외부 정보가 필요할 때만 수행. 불필요하면 "리서치 필요 없음 — 사유: ..." 한 줄로 기록 (스킵 금지).
   - **리서치 결과는 즉시 파일로 저장**: `.harness/research/research-<slug>-<NN>-<topic>.md`. 주제·조회 소스·핵심 발견 사항·도메인 설계에 미친 영향을 정리. 메인 컨텍스트에는 요약만 남기고 상세는 파일에서 참조 (컨텍스트 절약).
   - 도메인 설계 본문에서는 파일 경로로 인용 (예: "API rate limit 기준은 research-<slug>-01-rate-limit.md 참고").
4. skill 결과를 Codex 가 리뷰
5. 리뷰 결과를 메인 Claude 가 검토 / 반영
6. 사용자 승인 (클로드 선택모드:1번 승인하시겠습니까?) 승인질문할때는 계획을 화면에서 사용자가 확인 가능해야함.
7. 기타의견에 대해 수정이 필요한 경우 step2.2 로, 단순 질문인 경우 답변만, 그 후 다시 승인 질문
8. 사용자 승인 시 파일 작성 → step3 로
